# DATA MODEL

Каталог `data/` — канонический содержательный слой интерактивной документации KnockUI.

## sections.json

Определяет крупные разделы карты.

Обязательные поля:
- `id` — уникальный идентификатор;
- `title` — заголовок;
- `subtitle` — пояснение;
- `order` — порядок раздела на карте;
- `platform` — основной платформенный контур.

Чтобы добавить новый раздел, достаточно добавить объект в этот файл. HTML менять не нужно.

## cells.json

Каждая запись — отдельное техническое положение.

Основные поля:
- `id` — уникальный идентификатор;
- `section` — ID раздела из `sections.json`;
- `order` — позиция ячейки внутри раздела;
- `title`, `short`, `description`;
- `purpose` — назначение;
- `parameters` — параметры;
- `inputs`, `outputs`;
- `constraints`;
- `open_questions`;
- `status` — `approved`, `concept` или `needs-validation`;
- `platforms`, `models`, `tags`.

Положение ячейки в архитектуре задаётся данными `section + order`, а не HTML.

## relations.json

Каждая связь имеет:
- `from` — ID исходной ячейки;
- `to` — ID целевой ячейки;
- `relation` — человекочитаемая семантика;
- `type` — тип связи.

Допустимые `type`:
- `flow` — основной поток данных/действия;
- `branch` — ветвь, например fail-safe;
- `model` — архитектурная зависимость или реализация общей модели;
- `constraint` — ограничение;
- `strategy` — связь стратегии с реализацией;
- `roadmap` — связь этапа roadmap с компонентом;
- `governance` — связь процессов управления проектом.

Связи автоматически отображаются стрелками, попадают в подробную карточку и проходят runtime-проверку ссылочной целостности.

## gestures.json

Содержит алфавит, правило формирования пары и реальные назначения комбинаций. Свободные комбинации не нужно перечислять вручную.

## Прямая ссылка

Любая ячейка открывается через URL:

`#cell=<id>`

Например:

`https://slobodatablichka.github.io/4tap/#cell=android-quad-tap`
